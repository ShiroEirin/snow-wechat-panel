# snow-wechat-panel

Snow App 插件：**微信群聊面板**（信息流 + 统计/总结，单面板双视图）。

数据来自本机已安装的 **wechat MCP server**（[im-mcp](https://github.com/stkoecn/im-mcp) 的 `wechat-mcp`），面板**只读**，
不访问网络，不向微信发送任何消息。

> 当前版本 **`0.32.6`**：**单一面板**「微信群聊」，内部分段切换 **信息流 / 总结与报告 / MCP 工具台** 三个视图（群选择与时间范围共用；默认范围为**当天**）。

长图」功能重叠，产出还落到另一个面板里，属**负体验而非功能**。留存需求由导出覆盖，「让 AI 分析」需求由面板的「分析该成员 / 深度分析」直接满足（AI 读原始数据比读二手画像更准）；plugin.json 的 `memos` 域声明一并移除。④ **同步提示三态收口** —— 成功 3 秒淡出（成功不需要用户记住），失败 / 超时**常驻**并给「✕」手动关闭（错误要读要判断，自动消失会让人措手不及），「同步中」保持常驻到有结果。⑤ **图片解密失败的自我修复入口**（需重启 Snow App + 重装 MCP 生效）—— 微信 4.x 的聊天图片（`.dat`）有三代格式：旧 XOR 可离线反推密钥、V1 用固定常量、**V2 的 AES 密钥是账号级的，只在该账号查看图片时临时缓存于微信进程内存**，磁盘上没有任何副本。本机 12.8 万个 `.dat` 里 2026 年的图片 **100% 是 V2**，而 `all_keys.json` 里从来没有 `image_aes_key` 字段（上游 `key_tool` 只提取数据库密钥、从不提取图片密钥）—— 所以 V2 图片一直解不开，**并非近期回归**（2025 年的 1 万余张旧 XOR 图仍能正常解密，容易造成「以前好好的」的错觉）。本轮补齐闭环：MCP 新增 `extract_image_key` 工具（扫描微信进程内存中的 32 位 alnum 密钥候选，用真实 V2 密文块做**判定式**验证 —— 只有解出 JPEG/PNG/GIF/WEBP 文件头才算命中，命中后写入 `all_keys.json` 的 `image_aes_key`，后续解密自动生效）；面板在「图片未解密」卡片上补一条中文引导 + **「提取密钥」按钮**（一键调用该工具，成功后自动重试解密），工具台同步登记该工具。注意密钥只在微信查看图片时临时驻留内存，因此操作顺序是「先在微信客户端点开 1-2 张图 → 再点提取」。⑥ **表情包真图展示**（需重启 Snow App + 重装 MCP 生效）—— 此前结论「表情包不可行」是**错的**：表情消息的 `content` 虽然只有 `[表情]` 三个字，但**原始 XML 里带着 `md5`**（`<emoji ... md5="…">`，ETL 之前只取了标签、把 XML 丢了）。本轮打通整条链路：ETL 从 zstd 解压后的原始 XML 提取 md5 存入 `messages.emoticon_md5`（本机 31957 条表情消息命中 31955 条）；MCP 新增 `prepare_emoticons`（用社区工具 wxemo 搜一次账号 seed，再解出本机缓存的表情文件为明文库 `~/.wechat_mcp/emoticons/<md5>.<ext>`）与 `get_emoticon_image`（按 md5 取图）；面板的 `[表情]` 消息改为渲染**真实表情图**，取不到时**静默回退**成 `[表情]` 文本（历史表情常被微信清理，弹错只会让整屏变吵）。加密方案为账号级 `key = MD5(f"{seed}{wxid}EMOTICON")` + `AES-128-CBC(key, iv=key)`，`seed` 在 `0..2^32` 空间需 GPU 暴力搜索（实测 RTX 3080 约 3.5 秒）。**wxgf 私有容器按需转码**（首次约 1 秒、之后命中缓存）——批量转 1800+ 张要十分钟，属设计取舍而非缺陷；v0.32.1 **同步按钮改为阻塞执行**（需重启 Snow App 生效）—— 实测本机全量同步 72s（解密 ~6s + ETL ~66s），而宿主对单次 MCP 调用上限约 120s，因此不再走「`start_sync` 起独立进程 + 轮询状态」：短连接宿主会在 MCP 进程退出时终止该子进程，状态文件永不更新 → 按钮永远停在「同步中」（实测 `start_sync` 返回 `started=true`，但 `run_count` / `last_run.at` 从未变化，面板只能等到 15 分钟超时）。现改为直接阻塞调用 `sync_wechat_database`：只有一条路径，失败立刻可见；相关死代码（`SYNC_POLL_TIMEOUT_MS` / `syncPollRef` / `stopSyncPoll`）一并移除。MCP 侧同步修掉 `start_sync` 的假成功：worker 的 stdout/stderr 落盘 `~/.wechat_mcp/sync_worker.log`，并在 3s 宽限期内用**心跳里的 pid** 校验存活（它可能不是 Popen 的 pid —— uv 的 `python.exe` 是启动器，真实 worker 是它的子进程），失败即返回 `started=false` + 日志尾部并清理残留心跳；v0.32.2 修「引用块里的图片被误判成本条消息的图片」并让 AI 总结完成后立刻收敛（不再等轮询超时）；v0.32.3 **总结持久化** —— 完成时把正文 / 结构化数据 / 覆盖时间范围按会话存进 `api.storage`（key = `aiSummary:<sessionId>`），刷新面板或切群再回来自动回填，且绝不覆盖正在流式的会话；同时新增 `stripAiJson()` 把正文里裸露的 JSON 块剔掉（结构化数据由卡片单独渲染）；v0.32.4 **结构化数据块改用独有标记** `<<<AI_JSON>>>…<<<END>>>`（`parseAiData` 三级回退：独有标记 → ```` ```json ```` 围栏 → 正文里最后一个可解析对象，专门补救模型写残的 JSON），总结视图加分区图标与横条榜前三奖牌；v0.32.5 视觉再打磨（成员榜前三奖牌、争议指数改五星制、金句改引用卡，颜色一律跟随宿主主题）；v0.32.6 新增「**群友称号 · 乐子版**」卡片网格（复用 MCP `member_leaders` 的 11 个维度：水群王 / 话痨之王 / 连发狂魔 / 表情包发射器 / 斗图冠军 / 视频UP主 / 众矢之的 / 引用狂魔 / 深夜诗人 ## ⚠️ 硬性前置依赖：必须先装 wechat MCP

**本插件不内置任何微信数据采集能力**，全部数据来自本机安装的 **wechat MCP 服务器**。
没装 / 没启用时，两个面板都会显示安装引导页（不会空白或报错）。

四步：

1. 安装提供 `wechat-mcp` 的包（im-mcp 项目）——`pip install im-mcp` 或 `uv tool install im-mcp`
2. **以管理员身份**初始化本地微信索引（需微信已登录）——`wechat-init`
3. 在 Snow App → **设置 → MCP 服务器** 添加 stdio 服务器，**名称必须为 `wechat`**：

```json
{
  "mcpServers": {
    "wechat": {
      "command": "wechat-mcp",
      "args": [],
      "env": { "PYTHONUTF8": "1", "PYTHONIOENCODING": "utf-8" }
    }
  }
}
```

4. 若该 MCP 会话已在运行，重启应用 / 重连会话，然后回面板点「重新检测」

> 名称必须是 `wechat`：插件按 `wechat-<toolName>` 的形式调用工具（`toolFullName = <serverName>-<toolName>`）。

## 它做什么

### 视图一：信息流（`feed`）

- **群选择器**：拉取会话列表（默认只列群聊，含消息总数）
- **时间范围 + 关键词**：`get_messages_by_range`（按范围）/ `search_wechat_messages`（关键词搜索）
- **过滤**：只看媒体 / 只看 @ 提及
- **按天分组**（日期分隔线）；**发言者头像**（`get_user_avatars` 真头像圆形缩略图；缺缓存回退「首字母 + 稳定色」色块，同一人恒定同色）
- **类型徽标**：图片 / 视频 / 文件 / 语音 / 表情 / 链接
- 单次查询上限 200 条，触顶会提示缩小范围

### 视图二：总结与报告（`digest`）

- **报告类型**：日报 / 周报 / 月报 / 年报 / 自定义 —— 切换即自动设置时间窗并重查（MCP 只认 `start` / `end`，报告语义留在面板）。
- **趋势粒度随类型切换**：日报 = 24 小时；周报 / 月报 = 按天；年报 = 按月（前端从按天分布聚合）。
- **零 token 统计快路径**（MCP 在 SQL 侧全量聚合，不消耗模型 token）：
  - 概览卡：消息数 / 发言人数 / 人均 / 峰值；扩展卡：活跃率 / 集中度 Gini / 会话片段 / 撤回类事件
  - 趋势图（消息数 ⇄ 活跃人数切换，仅日报）
  - 成员榜（维度切换 + 点头像看发言分析）+ 参与度分桶 + 24×7 活跃热力
  - 消息类型占比（全量）
- **成员榜**：发言 / 字数 / 图片 / 表情 / 引用 / 被引用 / 连发 / 深夜 / 早起 多维切换（原「活跃发言者」已并入此处，不再重复画两遍）；点头像/行按需调 `get_member_profile` 展示统计画像。
  - 群自身（系统消息 / 群公告的发送者是群账号）不计入任何发言人维度，避免「群名出现在成员榜」。
- **AI 角色分析**：在成员画像里点「分析该成员」，新建 Agent 会话读该成员的近期发言，产出人物素描 / 关注点 / 语言风格 / 互动对象 / 金句 / 建议（与群分析共用同一条流式管线，互斥运行）。
- **互动网络**：引用消息解析出的被引用榜与「谁引用谁」Top 关系（含解析率）。
- **AI 深度分析**：新建一个 Agent 会话并把分析任务交给它（提示词里带上 `session_id` 与时间范围，优先调用 `get_group_digest` 取数），面板内流式渲染。
  - 解析末尾 json 块，渲染话题 / 热度 / 待办 / 风险 / 情绪曲线 / 争议指数 / 称号 / 金句 / 群画像
  - 提示词可在面板内展开预览
- **完整报告**：把当前报告类型下的概览 / 趋势 / 成员榜 / 互动网络 / 类型分布 / 金句候选 / AI 分析拼成 Markdown，可复制、保存 MD、保存 HTML 长图、打开文件。
  - 铁律：**MCP 负责通用聚合，面板负责展示，Snow App 负责落盘**（filesystem / 文件阅读器 / 剪贴板 / 定时任务）。

### 视图三：MCP 工具台（`mcp`）

把 wechat MCP 的 **28 个工具**直接摆到面板里，每个都能改参数、直接调用、看原始返回：

- 工具卡片列出**工具名 + 中文用途**，点开展开参数框（JSON，已按当前选中的群 / 日期预填 `session_id`、`start`、`end`）
- 「调用」后显示 **ok / 失败 · 耗时 ms · 返回条数**，以及完整返回体（可滚动）
- **同步微信数据**（`start_sync`，默认 `redecrypt: true`：先重新解密源库再重建索引）标记为**写操作**，需要点两次确认；后台执行 + 轮询状态，避免宿主 120s 硬超时
- **定时自动同步**（`set_auto_sync`）与 **定时同步状态**（`get_auto_sync_status`）也在工具台里，可直接开关
- 顶部显示本地索引规模（messages / sessions / contacts / media / avatars）

> 面板内调用与 Agent 用的是**同一套 wechat MCP**；除「同步微信数据 / 定时自动同步」外全部只读，不会向微信发送任何消息。

完整的架构设计、契约细节与开发避雷点见 **[DESIGN.md](./DESIGN.md)**。

### 聊天记录展开（v0.11.0）

`[聊天记录] …` 这类**合并转发消息**在本地索引里只有一行标题，被合并的正文要按需回取：

- 消息体渲染成折叠卡片（`ChatRecord`），默认收起；点开才发**一次** `get_chat_record(message_id)`
  （一屏可能几十条，不做预取）。
- 展开后逐条列出「谁 · 什么时候 · 内容」；图片 / 视频 / 文件等非文本条目给类型标签 + 文字占位。
- 读不到源库（解密快照缺失 / 该行已被清理）时只在卡片里提示错误，不影响其它消息渲染。

### 同步（v0.10.3）

- **顶栏控制行「同步」按钮**（在「查询」右侧）：一次完整同步 = **重新解密微信源库 → 重建本地索引**；改为调用 `start_sync` 后台执行、面板每 3 秒轮询 `get_auto_sync_status`，避免宿主对单次工具调用的 120s 硬超时（快照接近 1GB 时总耗时可能 1–3 分钟）。跑完显示绿条「同步完成 · N 条消息」。按钮自带旋转图标，同步中变为「同步中…」。
- **顶栏控制行「重置」按钮**：把群选择、日期范围（回到**当天**）、关键词、只看媒体 / 只看 @ 一次性恢复默认，并清空当前结果。
- **为什么必须重新解密**：微信源库是加密的，本地索引读的是**解密快照**。只重建 ETL 而不重新解密，拿到的永远是旧快照（这正是「今天一条消息都没有」的根因）。
- **定时同步**：面板与 Agent 都可通过 `set_auto_sync(enabled, interval_minutes)` 开启，间隔钳制 5–1440 分钟；`get_auto_sync_status` 查看开关、间隔、运行次数与上次结果。定时器随 MCP 进程存活（Snow App 启停）。

## ⚠️ 隐私声明

本插件在 `plugin.json` 中声明了 **`mcpSecrets` / `conversations` / `messages` / `filesystem` / `scheduledTasks`** 隐私域。

- **为什么需要**：`api.write.mcpTools.call` 的 `scope` 是 `mcpSecrets`，未声明则调用会被拒绝（`denied.reason = "write-declaration-missing"`）；AI 深度分析要通过 `messages` 读取新建会话的回复，报告要写入 `filesystem`；「定时日报」要通过 `scheduledTasks` 创建宿主定时任务。
- **风险提示**：**ESM 面板等价于本地代码，没有沙箱**。插件页会为此显示**琥珀色标签**。
- **本插件的实际行为**：通过 wechat MCP 工具**读取**本地微信消息索引，用于渲染信息流、统计与报告；渲染 `[图片]` 消息时自动调 MCP `get_message_image` 把 `.dat` 解密导出成真实图片文件，再经 `filesystem` 域用宿主 `window.snow.readFileContent(path)` 读取该文件并转成 `data:` URL 显示；顶栏「同步微信数据」会调 `start_sync` 在后台重新解密源库并重建本地索引；「报告」可复制到剪贴板、写入当前项目目录、通过内置文件阅读器打开；「定时日报」通过 `scheduledTasks` 在宿主「定时任务」面板创建每天执行的 AI Loop 任务（只在用户点击「创建定时日报」时创建）；不读取 API 密钥，不访问网络，不向微信发送任何消息。完整声明见 `plugin.json` 的 `privacy.note`。
- **作用域**：`mcpSecrets`（调用 MCP 工具）、`conversations`（AI 深度分析时新建会话）、`messages`（读取该会话的 Agent 回复）、`filesystem`（读取解密导出的图片、写入报告 MD / HTML 长图）、`scheduledTasks`（创建「定时日报」宿主定时任务）。
